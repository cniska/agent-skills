# Resume

Resume a coordinating session: its ledger, its workers and what they left, on this machine or another, in the cloud or under another account. A move to another machine or account needs the ledger in a pushed repo. There only pushed work exists: the task tool's machine-local store stays behind, so each worker whose brief is filed in the ledger's folder gets its task started in this machine's store before step 2 checks it, and the queued tasks the old store holds are named in the report as out of reach; a worker whose work is not on the remote restarts from its brief; and the old machine's checkouts are out of reach, so step 3 searches only the remotes and any checkouts here.

1. **Pull the ledger's repo, then read the ledger** and the shared file its `shared` key names, if any. Where a pull already ran at session start, read what it said: a failed pull leaves the ledger behind the remote. Another coordinator's ledger is not yours to resume: its workers, told apart as rule 4 says, stay with it.
2. **Take the in-flight list as rule 4 says**, keeping only your own workers, and the brief file each names. Before taking a worker as Partial or Not started and restarting it, read its last activity in the session record where one is installed, or in whatever list of agents the host offers: a worker active within its step's usual time is still running, such as after compaction, so it keeps going and gets a check-in as rule 6 says. Check each other worker against its repo's remote with `git ls-remote` and `git log`, not a tracking ref:
   - **Landed**: everything the brief asks is on the remote, and every CI run on its landed commit has finished green; wait for one still running, and count a red one as Partial. Close its task as done with its landed commits and delete its brief: `git log` holds what landed, and the ledger states only what is true now.
   - **Partial**: some of it is. Restart the worker from its brief, naming what already landed and what remains, with its open obstacles retaken from the ledger as it stands now.
   - **Not started**: none of it is. Restart the worker from its brief, with its open obstacles retaken from the ledger as it stands now.
   - **Given up**: work this session will not restart. Drop its task as rule 4's drop says.
   - A worker restarted with no task in the store gets its task started before it restarts.
3. **Look for work the ledger missed**: gather [the report's sources](report.md#sources) for every repo the ledger names, and read the previous session's last report from the session record.
4. **Review orphaned changes before trusting them**: uncommitted or unpushed work no live worker owns goes to a fresh reviewer, then lands, in the ledger's repo as rule 2 says and in a work repo only through a worker, joining a restarted worker's brief or a new task's brief, or is discarded on the owner's word. A change that joins a brief carries the last review verdict on it and the findings that review returned. Remove each worktree once its work landed and the landed commit's CI runs are green, a red one sent back as rule 8 says.
5. **Rewrite your own ledger before the first report**, leaving the shared file to hold only owner rules and decisions: what resume found that the ledger lacked, with each piece of work it found still to do queued as a task; the in-flight list keeps the workers still running or just restarted. Then build the report from what step 3 gathered.
