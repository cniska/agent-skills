# Update

`AGENTS.md` exists and a rule is changing. Merge the rule into the file rather than appending it.

When the request names no rule, such as bringing a drifted file up to standard, the skill's What matters is the incoming rule set: audit the whole file against it, and check each bullet still matches the code before keeping it, since a file free of duplicates can still state what stopped being true. Steps 2 and 3 apply per rule you land, and the rest to the pass as a whole.

1. Read the whole file first, so you know what each new rule could duplicate.
2. Find the section the rule belongs in, or for a rule no section fits, one from the menu in [create](create.md). Match the file's vocabulary and structure, and correct a term that is factually wrong or tool-specific.
3. **Merge into the file:**
   - where an existing bullet overlaps, rewrite that bullet to cover both.
   - where the rule generalizes several bullets, replace them with the one general rule.
   - where one rule is stated in two sections, keep it in its one correct home.
4. Trim the duplication the change exposes, and apply no drift from `principles` to what it made stale, outside the target section too.
5. Check the file still follows every rule in the skill's What matters, and that each agent tool the repo uses has a bridge.
6. Report which bullets you added, merged and trimmed, and why.
