# Current rules

A branch moves on, to the owner, to whoever lands it, or onto the branch it lands on, only once it is shown to meet the rules that hold now. Recheck it against each skill and agent definition that wrote or judged its commits:

1. **Find each one** from the loads in the session record where one is installed, else from the skills its task route and reviews name and the agent definitions that started its agents.
2. **Read what reached each one's source**, the repo its loaded path sits in, over the skill's directory and the agent definitions: each move of the checkout's HEAD after the time below that changed them, dated by the HEAD reflog, since a rebase resets commit dates, and any uncommitted change to them. A skill is read at the start of the branch's last review, taken from the session record where one is installed, else the time the branch was last sent out for review. An agent definition is read at the start of the top-level session that started the branch's agents, taken from the session record; where nothing dates that start, treat the definition as a source that cannot be read.
3. **Sort the result.** With no change there, the branch's reviews still hold. A change there, or a source that cannot be read, means the branch is not shown to meet the rules that hold now; the skill that names this principle says where it goes.

A running session reads a skill's current text each time it loads it with the Skill tool, and a subagent reads each skill it preloads as it stands when that subagent starts. An agent definition stays as the top-level session read it at its start, until its plugins reload, so a running session cannot load a changed one.
