# Owner's order

Order work by how the owner will use the product, never by the order a spec, plan or backlog happens to list it.

- Before you order a queue, a plan's phases or a feature's slices, state in one sentence what the owner would do first with the product today, and what next. Order by that.
- Of two ways into a feature, build first the one the owner reaches first, such as importing from the app they use now before a file they would have to make by hand.
- When that order is unclear, ask the owner how they will use it, with the order you recommend. The spec's listing is never the answer.
- An owner's ask comes before work that only serves the workflow, such as tooling, an audit, a verify skill's gaps or doc drift. When that work blocks the ask, it is ordered as part of the ask.
